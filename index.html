Overview

From One Bill to Clear Accountability

Without attribution, every credit is "IT overhead" and no one owns the spend. In this guide you tag resources to business units, add guardrails and budgets, and then answer "who spent what?" with a few queries on built-in views.

1

Tag

Label warehouses, users and databases with a governed COST_CENTER tag, so every credit has an owner.

2

Guard

Resource monitors cap warehouse credits, and auto-suspend and statement timeouts cut idle and runaway spend.

3

Budget

Tag-based custom budgets track compute and serverless spend per team and alert before limits are reached.

4

Charge back

ACCOUNT_USAGE queries split dedicated and shared costs per business unit and flag waste and spikes.

Prerequisites

Before You Begin

  • Snowflake Enterprise Edition or higher. Object tagging and tag-based custom budgets require it.
  • ACCOUNTADMIN, or <YOUR_ROLE> with CREATE WAREHOUSE, CREATE DATABASE, CREATE USER, CREATE ROLE and APPLY TAG on the account. Only ACCOUNTADMIN can create resource monitors.
  • Access to SNOWFLAKE.ACCOUNT_USAGE. ACCOUNTADMIN has it by default. Other roles need IMPORTED PRIVILEGES on the SNOWFLAKE database.
  • A Snowsight SQL worksheet. The script creates its own prefixed objects (CB_* and CHARGEBACK_DEMO_DB) and changes nothing that already exists.
  • Patience for latency. ACCOUNT_USAGE views lag by minutes to hours, so the queries in Steps 7–8 fill in over time.
1
Step 1

Create Demo Resources

This step creates the resources a real account already has: PROD and DEV warehouses for each business unit, two shared warehouses, a database per unit and five demo users. Warehouses are XSMALL and start suspended, and the users are service users with no credentials, so they cost nothing and can't log in.

2
Step 2

Create Cost Tags

Three tags drive everything: COST_CENTER (who pays), ENVIRONMENT (PROD vs. DEV) and an optional free-form PROJECT tag. ALLOWED_VALUES makes COST_CENTER a governed list, so a typo like "Sales " can't quietly create an orphaned cost bucket.

3
Step 3

Tag Warehouses, Users and Databases

Each object type answers a different question. Warehouse tags attribute dedicated compute, user tags split shared warehouses by who actually ran the queries, and database tags attribute storage. In production, apply the tags in your provisioning automation so nothing is ever created untagged.

4
Step 4

Resource Monitors and Guardrails

Resource monitors are the hard stop. Each business unit's warehouses share a monthly credit quota that notifies at 75% and 90% and suspends at 100%. Short auto-suspend times and statement timeouts address the two most common sources of waste: idle warehouses and runaway queries.

The account-level monitor (4a) is commented out on purpose. It applies to every warehouse in the account and suspends them all at its limit. Size the quota to your real usage before you enable it.
5
Step 5

Tag-based Custom Budgets

Budgets close the gap that resource monitors leave: they include serverless features such as Snowpipe, tasks and auto-clustering, and they alert on projected spend. Because each budget is scoped by the COST_CENTER tag, a newly tagged resource is added to the right budget automatically.

New budget scopes can take up to six hours to show usage. To see results sooner, call <budget>!REFRESH_USAGE().
6
Step 6 · Optional

Generate a Sample Workload

A new account has no usage history, so the reports would come back empty. A few short queries on the dedicated warehouses create some metering, well under one credit in total. To try shared-warehouse attribution, tag your own user and run a query on the shared warehouse.

7
Step 7

Chargeback Queries

These queries join usage views to TAG_REFERENCES to answer "who spent what?" Dedicated warehouses map straight to their owner. Shared warehouses are split with QUERY_ATTRIBUTION_HISTORY, which assigns credits to each query, and the user tags then roll those queries up to business units.

Step 9 · Optional

Going Multi-Account

If each business unit has its own Snowflake account, define the tags once and replicate them so every account uses identical values. Then roll costs up from the organization account with ORGANIZATION_USAGE. Replace the <YOUR_ORG> and account placeholders with your own identifiers.

10
Step 10

Clean Up

Uncomment and run this block to remove everything the demo created. Tagged objects are dropped before CHARGEBACK_DEMO_DB, which holds the tags and budgets. If you tagged your own user in Step 6, unset that tag first.

Wrap-up

Key Takeaways

Cost accountability in Snowflake needs no extra tooling: tags, guardrails, budgets and built-in usage views cover it.

Tag at creation time

Governed tag values applied by your provisioning automation keep every credit attributable from day one.

Shared costs can be fair

User tags and QUERY_ATTRIBUTION_HISTORY split shared warehouses by actual usage instead of an even split.

Prevent, then report

Monitors and budgets stop overspend as it happens. Chargeback queries explain it after the fact.

Look for waste

Idle warehouses, runaway queries and sudden spikes are the fastest savings, and one query finds each.
